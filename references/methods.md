# 方法选择与扩展

这里是按问题组织的能力目录，不是必须依次执行的步骤，也不是工具白名单。当前方法不能解释现象时，选择其他工具、组合方法、编写脚本或向用户取得具体证据。

## 调查循环

为关键未知项记录：关联功能 ID、问题、候选解释、实验输入和前置状态、工具与版本、输出路径、结论及未解决项。优先选择能区分候选解释的最小实验。先核对实际可调用能力及其文档，再执行；不要把工具宣传、静态伪代码或模型记忆直接当成已验证规格。

| 要回答的问题 | 可选择的方法 | 必须核对的结果 |
| --- | --- | --- |
| 有哪些入口与功能？ | 包结构、Info.plist、AX、GUI、AppleScript 字典、资源文案、帮助文档、版本说明、代码中的事件注册 | 入口是否实际可达，何种状态可用，是否只是过时资源 |
| 某次操作如何改变状态？ | 受控输入、前后快照、文件与数据库检查、系统日志、文件访问追踪、函数调用观察 | 前置状态、变化内容、持久化时机、失败和重启后的状态 |
| 算法、格式或默认值是什么？ | 静态反编译、符号与交叉引用、资源解析、边界输入、差分实验、自写解析器 | 输入输出、编码与舍入规则、边界条件；将推断回到原版验证 |
| 内部路径为什么不同？ | LLDB、Frida 或其他适用的调试与插桩工具，断点、调用参数和返回值、受控重放 | 目标版本、架构、权限、调用顺序；插桩是否改变原版行为 |
| 是否依赖服务端？ | 依赖检查、测试账号下的网络观察、请求响应与本地状态关联、可控制服务的协议测试 | 哪些状态在客户端，哪些在服务端；离线行为、认证和错误分支 |
| 为什么视觉或交互不同？ | GUI 实测、录屏或逐帧观察、AX 与视图信息、截图测量、实际拖放和键盘测试 | 窗口尺寸、语言、系统外观、缩放、焦点、动效和原生控件行为 |
| 哪种实现能可靠复现？ | 系统框架、公开算法、兼容库、原生或跨平台 UI、小型技术验证 | 真实功能、构建与运行依赖、可维护性及对原版的差异 |
| 是否已经匹配行为？ | A/B 同输入差分、自动化与 GUI 回归、边界输入和变形测试、人工体验 | 检查可见结果和副作用；确认预期结果来自原版而非 B 自己 |

## 针对技术栈调整

**原生应用**：按需要检查 Mach-O、Objective-C/Swift 元数据、链接库、nib/storyboard、资源、Helper 和 XPC。可通过 REA 的可用 provider，或直接使用适合的反编译器和调试器。不要要求先恢复全部内部源码才开始实现。

**Electron、WebView、Qt 或其他跨平台应用**：检查实际包结构、资源、脚本、模块和事件注册，使用适合该技术栈的解析或运行时工具。能提取的代码属于分析材料；提取成功不代表功能已经验证，也不自动获得其再分发权限。

**文件、音视频、图像和开发工具**：优先识别格式、算法和已有可用组件，用小规模输入输出实验确认兼容性。可以复用公开库和系统能力，不为了“独立实现”重复编写成熟基础设施；固定依赖版本并保存许可信息。

**联网能力**：允许网络通信。关键是 B 的行为和状态是否能由交付实现及可控制依赖提供。真实账号和不可控制私有平台不能由占位界面替代；对可自建的服务提供实际状态、重置和测试数据，并明确与 A 的差异。

## 能力扩展与失败处理

安装新工具前确认现有能力不足、运行环境和安装范围。使用官方文档核实当前 CLI/API，保存实际版本和命令。对第三方脚本先检查内容；新工具失败时保留错误与替代方案，不把一次失败写成目标不可能实现。

调试、插桩或分析副本可能受到代码签名、系统保护和目标架构限制。先确认可用权限与受支持方式。需要付费、系统安全设置变更、账号访问或破坏性操作时取得对应授权；不自动关闭系统保护、不读取无关账户数据。修改过的分析副本和未修改原版分开标识，外部行为最终回到原版核验。

可以让子 Agent 分别调查功能区、实现模块或执行测试，但共享稳定的功能 ID、证据目录和接口约定。避免同时修改同一原版状态或同一源文件；合并后由主 Agent 重新验证，不把子任务完成等同于最终完成。

## 证据类型不绑定供应商

继续使用现有 `bundle / ax / state / gui / file / log / rea / doc / user`；任意静态分析工具使用 `static`，任意运行时分析或受控实验使用 `runtime`。两种通用类型都必须提供证据文件路径，在 `note` 记录工具、版本、目标和结论。静态推断只能支持候选解释，运行时结果必须来自实际目标实验。

新工具的输出包含凭据或个人数据时，先保存必要的脱敏证据。原版二进制、专有资源、账户数据和具体参考实现都不进入公共 Skill 仓库。
